The problem isn’t encryption. It’s the steps.

The old way

  • Files are uploaded to third-party cloud storage.
  • Archive passwords are sent in the same channel.
  • No one knows who holds copies.
  • Desktop encryption tools require installs and new habits.

With AegisCrypt

  • Encryption runs locally using the Web Crypto API.
  • You share the encrypted file, not the original.
  • Open format, readable by web and desktop versions.
  • No installation required.

Three steps, no upload

  1. 01

    Choose files

    Select the files you want to encrypt. They stay on your device.

  2. 02

    Set a password

    Keys are derived with PBKDF2-HMAC-SHA256 and used for AES-256-GCM. An optional keyfile can be added.

  3. 03

    Share the .aegis file

    The encrypted file is ready to send. The recipient opens it with the password you share over a separate channel.

What you can verify yourself

Open specification

128-byte header, record layout, and AAD are documented and frozen as a contract.

Read the v3 format

Two implementations

Web (TypeScript) and desktop (.NET 8) are tested against the same frozen vectors, including Unicode password vectors.

See architecture

Fail closed

Every authentication failure aborts and discards partial output. Production headers use strict CSP and HSTS.

Security notes

AegisCrypt has not been independently audited. Do not rely on it as the only copy of important files.
