Dokumentasi.

Referensi teknis lengkap untuk klien browser AegisCrypt: mesin AES-256-GCM, container .aegis v2, API kriptografi publik, dan deployment Cloudflare yang melayani semuanya — tanpa unggah file, tanpa server, tanpa pengetahuan server.

Sandi

AES-256-GCM

Enkripsi terotentikasi mendeteksi penyusupan. Sebuah bit yang berubah dalam ciphertext atau tag akan membuat dekripsi gagal.

KDF

PBKDF2 100K

HMAC-SHA-256 dengan 100.000 putaran dan garam 32 byte segar per file menghasilkan kunci AES 256-bit yang tidak dapat diekstrak.

2FA

Keyfile

Materi kunci adalah byte sandi diikuti oleh SHA-256(keyfile). Keyfile yang persis sama diperlukan untuk mereproduksi kunci.

Stream

1 MiB bagian

Enkripsi memotong file besar menjadi blok 1 MiB dengan IV baru per blok dan menyimpan output sebagai bagian Blob.

Lokal

Tanpa backend

Tidak ada endpoint unggah, sistem akun, atau penanganan kunci di sisi server. Aplikasi yang di-deploy adalah HTML, CSS, dan JavaScript statis.

Integritas

Parsing ketat

Magic bytes, versi, dan panjang bagian divalidasi sebelum dekripsi; container yang rusak ditolak.

Artinya “tanpa pengetahuan server” di sini

Aplikasi tidak dapat membaca file Anda setelah sesi berakhir karena tidak pernah mengirimkannya ke mana pun. Browser menghasilkan kunci dan mengenkripsi secara lokal, lalu mengunduh container. Permintaan eksternal satu-satunya adalah untuk aset statis dan stylesheet Google Fonts opsional.

03

Arsitektur

Setiap file mengikuti pipeline yang sama. Derivasi kunci terjadi di dalam operasi file, bukan saat masuk, sehingga garam baru dapat dihasilkan per file.

Input Sandi + Keyfile
→
KDF PBKDF2-SHA256
→
Sandi AES-256-GCM
→
Output Container .aegis

Urutan enkripsi

  1. Hasilkan garam 32 byte dengan crypto.getRandomValues.
  2. Bangun materi kunci: byte sandi UTF-8, diikuti oleh hash SHA-256 32 byte dari keyfile jika ada.
  3. Impor materi kunci sebagai input PBKDF2 dan turunkan kunci AES-GCM 256-bit dengan 100.000 iterasi. Kunci tidak dapat diekstrak.
  4. Tulis header 38 byte: AEGIS, versi 0x02, lalu garam.
  5. Untuk setiap irisan plaintext 1 MiB, buat IV baru 12 byte, enkripsi, dan paketkan hasilnya.
  6. Kumpulkan header dan catatan bagian sebagai bagian Blob dan unduh container yang selesai.

Urutan dekripsi

  1. Baca seluruh container ke dalam ArrayBuffer.
  2. Validasi 5 byte magic dan byte versi sebelum membaca bagian apa pun.
  3. Baca garam 32 byte, bangun kembali materi kunci, dan turunkan kunci AES yang sama.
  4. Untuk setiap catatan, baca panjang 4 byte little-endian, validasi terhadap byte yang tersisa, lalu pisahkan IV dan ciphertext.
  5. Dekripsi setiap bagian; kegagalan GCM dilaporkan sebagai sandi salah, keyfile salah, atau penyusupan.
  6. Kumpulkan bagian plaintext ke dalam Blob dan unduh file yang dipulihkan.

04

Penggunaan

Enkripsi

Segel berkas

  1. Masukkan sandi utama yang kuat.
  2. Opsional: aktifkan keyfile dan pilih berkas.
  3. Klik Mulai Sesi.
  4. Seret berkas atau folder ke antrian.
  5. Klik Enkripsi. Satu unduhan dipicu per berkas.
  6. Izinkan unduhan banyak jika browser meminta.
Dekripsi

Pulihkan berkas

  1. Gunakan sandi dan keyfile yang persis sama seperti saat enkripsi.
  2. Seret berkas .aegis ke antrian.
  3. Klik Dekripsi.
  4. Nama file asli dipulihkan saat container diakhiri dengan .aegis.
  5. Verifikasi berkas yang dipulihkan sebelum menghapus container.

Perilaku antrian

  • Berkas diproses secara berurutan, dalam urutan yang ditampilkan di antrian.
  • Antrian menerima banyak berkas dan pemilihan folder melalui pemilih berkas atau seret lepas.
  • Setiap berkas diunduh terpisah; browser mungkin memblokir unduhan otomatis banyak hingga Anda mengizinkannya.
  • Batal menghentikan di antara bagian. Karena unduhan dibuat hanya setelah berkas selesai, berkas yang dibatalkan tidak menghasilkan unduhan sebagian.
  • Setiap berkas berhasil, antrian dikosongkan secara otomatis. Berkas yang gagal tetap berada di antrian untuk diperiksa.
Semantik progres

Selama enkripsi, progres menghitung byte plaintext. Selama dekripsi, progres menghitung byte container, termasuk header dan overhead per bagian, jadi persentase relatif terhadap ukuran container.

05

Format File

Container .aegis v2 adalah header 38 byte diikuti oleh satu atau lebih catatan bagian dengan awalan panjang. Semua bilangan bulat little-endian.

Header (38 byte)

OffsetUkuranBidangNilai
05MagicASCII AEGIS (41 45 47 49 53)
51Versi0x02
632SaltByte CSPRNG, unik per file

Catatan bagian (berulang)

BidangUkuranDetail
Panjang4 byteLittle-endian; sama dengan 12 + panjang ciphertext, termasuk tag GCM 16 byte
IV12 byteNilai CSPRNG segar untuk setiap bagian
Ciphertext + tagpanjang − 12Output AES-GCM; tag adalah 16 byte terakhir

Perhitungan ukuran

Untuk file yang dibagi menjadi n bagian, ukuran container adalah:

rumus 
container = 38 + fileSize + (32 × n)

# per bagian: panjang 4 byte + IV 12 byte + tag GCM 16 byte
# bagian penuh 1 MiB: 4 + 12 + 1.048.576 + 16 = 1.048.608 byte
  • Container tidak menyimpan nama berkas, ukuran asli, tipe MIME, stempel waktu, atau metadata kompresi.
  • Nama file output hanya konvensi UI: nama.ext menjadi nama.ext.aegis.
  • Berkas input kosong valid: enkripsi hanya menulis header 38 byte, dan dekripsi mengembalikan berkas kosong.
  • Bidang header tidak diteruskan sebagai data terotentikasi tambahan AES-GCM. Garam yang rusak menghasilkan kunci salah dan kegagaan GCM; versi yang rusak ditolak sebelum dekripsi.
  • Hanya versi 2 yang diterima. Container versi 1 dan versi yang tidak diketahui ditolak, bukan diurai dengan layout yang salah.
Kompatibilitas

Container versi 2 dimaksudkan untuk interoperabilitas dengan implementasi desktop AegisCrypt yang menggunakan layout bagian yang sama. Selalu lakukan uji round-trip dengan berkas yang tidak penting sebelum mengandalkan pertukaran lintas platform.

Referensi API

Mesin kripto tinggal di src/services/cryptoService.ts. Setiap fungsi menggunakan window.crypto.subtle dan berjalan di browser.

example.ts 
import {
  processFileEncrypt,
  processFileDecrypt,
  downloadBlob,
} from "./services/cryptoService";

const controller = new AbortController();

const sealed = await processFileEncrypt(
  file,
  password,
  keyFileBuffer,          // ArrayBuffer | null
  controller.signal,
  (plaintextBytes) => console.log(`${plaintextBytes} byte dibaca`)
);

downloadBlob(sealed, `${file.name}.aegis`);

const restored = await processFileDecrypt(
  await sealed.arrayBuffer(),
  password,
  keyFileBuffer,
  controller.signal,
  (containerBytes) => console.log(`${containerBytes} byte dibaca`)
);

downloadBlob(restored, file.name);

08

Model Keamanan

AegisCrypt melindungi data saat diam dan saat diteruskan setelah disegel. Ini tidak melindungi endpoint yang sudah terkompromi, dan tidak dapat memulihkan kredensial yang lupa.

Dalam skope

Apa yang dilindungi

  • Berkas yang disimpan di disk atau drive cloud yang tidak terpercaya
  • Berkas yang dikirim melalui saluran yang tidak aman
  • Modifikasi ciphertext tanpa sengaja, terdeteksi oleh GCM
  • Tebakan sandi dilambatkan oleh peregangan PBKDF2
  • Kepemilikan keyfile sebagai faktor kedua
Luar skope

Apa yang tidak dapat dilindungi

  • Perangkat, browser, atau ekstensi yang sudah terkompromi
  • Malware, pencetus kunci, atau perekam layar berbahaya
  • Sandi yang lemah, digunakan kembali, atau ditangkap by fishing
  • Kehilangan sandi atau keyfile
  • Paparan metadata seperti nama berkas dan ukuran berkas

Siklus hidup kunci

  • Sesi menyimpan string sandi dan buffer keyfile ArrayBuffer opsional dalam status React hingga logout, reload, atau penutupan tab.
  • Garam baru 32 byte dihasilkan untuk setiap berkas terenkripsi. Sandi dan keyfile di-hash ulang menjadi materi kunci untuk setiap operasi.
  • Kunci AES yang diturunkan non-ekstraktibel dan hanya ada sebagai CryptoKey selama operasi berlangsung.
  • Keyfile itu sendiri tidak ditulis ke dalam container; hanya hash SHA-256-nya yang berkontribusi pada materi kunci.
  • Tidak ada kunci, sandi, atau plaintext yang disimpan ke localStorage, IndexedDB, cookie, atau server.

Catatan implementasi

  • Enkripsi stream irisan 1 MiB dan menyimpan output sebagai bagian Blob, menghindari alokasi tunggal yang besar.
  • Dekripsi saat ini membaca seluruh container ke dalam memori dan mengumpulkan setiap bagian plaintext sebelum membuat output Blob.
  • Setiap bagian menerima IV segar 12 byte. Garam unik per file, bukan per bagian.
  • Panjang bagian divalidasi sebelum pemotongan untuk menolak container yang rusak atau terpotong.
  • Salah kredensial dan ciphertext yang disusupi sama-sama muncul sebagai pesan kegagalan GCM.
  • Header tidak diotentikasi dengan data terotentikasi tambahan AES-GCM. Magic dan versi diperiksa secara eksplisit; garam secara implisit diotentikasi karena garam salah menghasilkan kunci salah.

Batasan yang diketahui

  • JavaScript tidak dapat memastikan pengosongan memori. String sandi dan buffer keyfile mungkin tetap ada dalam memori tab hingga pemuntahan sampah.
  • Tidak ada kunci otomatis, waktu tunggu idle, atau otentikasi ulang.
  • PBKDF2-HMAC-SHA-256 pada 100.000 iterasi adalah pilihan kompatibilitas. OWASP saat ini merekomendasikan 600.000 iterasi untuk konstruksi ini, jadi gunakan sandi panjang dan berentropi tinggi.
  • Nama berkas tidak dienkripsi; nama unduhan mengungkap nama asli dan akhiran .aegis.
  • Aplikasi tidak bertahan terhadap build yang terkompromi, dependensi berbahaya, atau penyerang yang dapat mengeksekusi skrip di halaman.
Saran operasional

Gunakan sandi panjang dan unik, simpan keyfile terpisah dari container, simpan cadangan offline, dan uji dekripsi dengan berkas sampel sebelum menghapus aslinya. Pemulihan sepenuhnya merupakan tanggung jawab Anda.

09

Performa & Batasan

Enkripsi dirancang untuk berkas besar. Dekripsi lebih sederhana dan menggunakan lebih banyak memori karena membutuhkan seluruh container dan semua bagian plaintext sekaligus.

OperasiModel memoriImplikasi praktis
EnkripsiMembaca satu bagian plaintext 1 MiB setiap kali; menyimpan output sebagai bagian BlobBekerja untuk berkas multi-gigabyte dengan jejak heap modest
DekripsiMembaca seluruh container ke dalam ArrayBuffer dan menyimpan setiap bagian yang didekripsiMemori puncak sekitar ukuran container ditambah ukuran plaintext; berkas yang sangat besar dapat kehabisan tab
BatalDiperiksa sebelum setiap bagianPembatalan responsif dalam satu bagian; tidak ada unduhan sebagian yang dihasilkan
ProgresEnkripsi: byte plaintext. Dekripsi: byte containerPersentase dekripsi termasuk overhead header dan bagian

Overhead container

Setiap bagian menambahkan 32 byte: 4 untuk panjang, 12 untuk IV, dan 16 untuk tag GCM. File 10 GiB yang dibagi menjadi 1 MiB bagian memiliki 10.240 bagian dan sekitar 320 KiB overhead, ditambah header 38 byte.

Dukungan browser

BrowserStatusCatatan
Chrome / EdgeDidukungTarget pengembangan utama; README melaporkan pengujian hingga 10 GB pada Chrome 120+
FirefoxDidukungMemerlukan Web Crypto dan dukungan File/Blob
SafariDidukungVersi modern dengan crypto.subtle; uji berkas besar pada versi target
Internet ExplorerTidak didukungTidak ada Web Crypto API
Kecepatan dan ETA

Dasbor menghitung kecepatan dari byte plaintext yang diproses dan waktu dinding yang berlalu, dan memperkirakan waktu yang tersisa dari file saat ini. Nilai direset per berkas; bukan benchmark yang terkalibrasi.

10

Pengujian

Repositori ini dilengkapi dengan suite Vitest crypto dan perjalanan pengguna Playwright kecil. Keduanya berjalan lokal tanpa backend.

perintah pengujian 
npm run test:unit    # 6 uji di tests/cryptoService.test.ts
npm run test:e2e     # 2 uji di tests/e2e/app.spec.ts
Unit

Apa yang dicakupi Vitest

  • Panjang dan keacakan salt dan IV
  • Derivasi kunci AES-GCM-256 dan non-ekstraktibilitas
  • Enkripsi/dekripsi round trip hanya sandi
  • Round trip keyfile; keyfile yang hilang atau salah ditolak
  • Pembatalan sinyal abort
  • Penolakan panjang bagian yang tidak valid
E2E

Apa yang dicakupi Playwright

  • Sandi diperlukan sebelum sesi dimulai
  • Tombol Mulai Sesi nonaktif saat kosong
  • Sandi yang valid membuka ruang kerja pemrosesan
  • Antrian, Enkripsi, Dekripsi, dan Logout terlihat

Suite e2e menggunakan vite preview di 127.0.0.1:4173 dan Chromium melalui Playwright.

FAQ

Apakah saya bisa memulihkan berkas tanpa keyfile?

Tidak. Jika keyfile digunakan, materi kunci mencakup SHA-256(keyfile). Tanpa byte yang persis sama, PBKDF2 menurunkan kunci berbeda dan dekripsi GCM gagal.

Apakah Mulai Sesi menurunkan kunci enkripsi?

Tidak. Ini menyimpan sandi dan buffer keyfile opsional. Setiap operasi file menghasilkan garam segar dan menurunkan kunci baru, jadi sandi yang sama menghasilkan kunci berbeda untuk container yang berbeda.

Apakah AegisCrypt mengirimkan sesuatu ke server?

Tidak ada konten file, byte sandi, byte keyfile, atau kunci turunan yang dikirim. Aplikasi adalah bundel statis; satu-satunya permintaan jaringan adalah untuk aset aplikasi dan stylesheet Google Fonts. Kripto tetap bekerja setelah halaman dimuat bahkan jika jaringan putus.

Apakah nama file dienkripsi?

Tidak. Container tidak menyimpan metadata nama berkas, tetapi berkas yang diunduh dinamai original.ext.aegis, yang mengungkap nama dan ekstensi asli. Ubah nama container jika nama file sensitif.

Mengapa dekripsi gagal dengan sandi yang benar?

Keyfile mungkin berbeda, container dimodifikasi, atau berkas terpotong. GCM autentikasi menolak ketiga hal tersebut. Periksa sumber hash keyfile dan pulihkan container dari cadangan.

Apakah berkas besar didukung?

Enkripsi stream bagian 1 MiB dan menyimpan output sebagai bagian Blob. README melaporkan pengujian hingga 10 GB di Chrome 120+. Dekripsi adalah langkah yang terbatas karena membuffer seluruh container dan semua bagian plaintext.

Apakah berkas kosong dapat dienkripsi?

Ya. Loop hanya menulis header 38 byte, dan dekripsi mengembalikan berkas kosong. Container tetap versi 2 dan membawa garam nyata.

Apakah format kompatibel dengan versi desktop?

Layout bagian v2 dimaksudkan untuk cocok dengan implementasi desktop AegisCrypt. Selalu jalankan uji round-trip dengan berkas yang tidak penting sebelum mengandalkan pertukaran lintas platform.
